# 输出格式说明

## 问题类型与输出格式

### 1. 简单问题

**问题类型**: 引脚配置、通信参数、函数功能等

**输出格式**:
```
Q: <问题>

A: <答案>

证据：
- <文件>:<行号>: <代码>
- <文件>:<行号>: <代码>

置信度: <高/中/低>（<原因>）
```

**示例**:
```
Q: LED 接在哪个引脚？

A: PB5（GPIOB, Pin 5）

证据：
- led.c:12: GPIOB->CRL |= (0x3 << 20);  // PB5 推挽输出
- led.c:15: GPIOB->ODR |= (1 << 5);      // 高电平点亮

置信度: 高（源码和文档一致）
```

### 2. 整体分析

**问题类型**: "这个程序是干什么的？"

**输出格式**:
```
=== 程序整体分析 ===

【程序名称】<程序名称>
【主控芯片】<芯片型号> (<架构>, <特性>)
【主要功能】
  1. <功能1> (<外设>)
  2. <功能2> (<外设>)
  3. <功能3> (<外设>)

【架构特点】
  - <特点1>
  - <特点2>
  - <特点3>

【关键文件】
  - <文件1>: <功能1>
  - <文件2>: <功能2>
  - <文件3>: <功能3>
```

**示例**:
```
=== 程序整体分析 ===

【程序名称】智能家居控制器
【主控芯片】STM32F103C8T6 (ARM Cortex-M3, 72MHz)
【主要功能】
  1. 温湿度检测 (DHT11)
  2. LED 灯光控制 (PWM)
  3. 串口通信 (UART)

【架构特点】
  - 分层架构：APP → BSP → HAL
  - 使用 FreeRTOS 任务调度
  - 支持调试串口

【关键文件】
  - main.c: 主程序入口
  - bsp_dht11.c: 温湿度传感器驱动
  - app_led.c: LED 控制逻辑
```

### 3. 功能列表

**问题类型**: "用了哪些外设？"

**输出格式**:
```
=== 功能模块列表 ===

| 功能 | 文件 | 说明 |
|------|------|------|
| <功能1> | <文件1> | <说明1> |
| <功能2> | <文件2> | <说明2> |
| <功能3> | <文件3> | <说明3> |
```

**示例**:
```
=== 功能模块列表 ===

| 功能 | 文件 | 说明 |
|------|------|------|
| 温湿度检测 | bsp_dht11.c | DHT11 传感器驱动 |
| LED 控制 | app_led.c | LED 灯光控制 |
| 串口通信 | bsp_uart.c | UART 通信 |
```

### 4. 代码提取建议

**问题类型**: "我想用这个程序的 xxx 功能"

**输出格式**:
```
=== 代码提取建议 ===

【用户需求】<需求描述>

【需要提取的文件】
  1. <文件1>
  2. <文件2>
  3. <文件3>

【需要修改的部分】
  1. <修改1>
  2. <修改2>

【依赖的其他模块】
  - <模块1>（<说明>）
  - <模块2>（<说明>）

【使用方法】
  1. <步骤1>
  2. <步骤2>
  3. <步骤3>
```

**示例**:
```
=== 代码提取建议 ===

【用户需求】使用 DHT11 温湿度传感器

【需要提取的文件】
  1. bsp_dht11.c
  2. bsp_dht11.h

【需要修改的部分】
  1. GPIO 引脚配置（根据实际硬件修改）
  2. 时序延时函数（根据主频修改）

【依赖的其他模块】
  - HAL 库（GPIO 初始化）
  - 延时函数（us 级延时）

【使用方法】
  1. 初始化：DHT11_Init()
  2. 读取数据：DHT11_Read(&temperature, &humidity)
  3. 使用数据：temperature, humidity
```

### 5. 代码搜索结果

**问题类型**: "帮我搜索 xxx 函数"

**输出格式**:
```
=== 搜索结果 ===

【搜索关键词】<关键词>
【搜索范围】<目录>
【找到 <N> 个结果】

| 文件 | 行号 | 内容 |
|------|------|------|
| <文件1> | <行号1> | <内容1> |
| <文件2> | <行号2> | <内容2> |
| <文件3> | <行号3> | <内容3> |
```

**示例**:
```
=== 搜索结果 ===

【搜索关键词】DHT11_Read
【搜索范围】整个项目
【找到 3 个结果】

| 文件 | 行号 | 内容 |
|------|------|------|
| bsp_dht11.c | 45 | uint8_t DHT11_Read(uint8_t *temp, uint8_t *humi) |
| app_sensor.c | 23 | DHT11_Read(&temperature, &humidity); |
| main.c | 67 | DHT11_Read(&temp, &humi); |
```

### 6. 函数分析

**问题类型**: "这个函数是什么意思？"

**输出格式**:
```
=== 函数分析 ===

【函数名】<函数名>
【文件】<文件名>:<行号>
【功能】<功能描述>

【参数】
  - <参数1>: <说明1>
  - <参数2>: <说明2>

【返回值】<返回值说明>

【实现逻辑】
  1. <步骤1>
  2. <步骤2>
  3. <步骤3>

【调用关系】
  - 调用: <函数1>, <函数2>
  - 被调用: <函数3>, <函数4>
```

**示例**:
```
=== 函数分析 ===

【函数名】DHT11_Read
【文件】bsp_dht11.c:45
【功能】读取 DHT11 温湿度传感器数据

【参数】
  - temp: 温度值指针（单位：℃）
  - humi: 湿度值指针（单位：%）

【返回值】0=成功, 1=失败

【实现逻辑】
  1. 发送起始信号（拉低 18ms）
  2. 等待 DHT11 响应
  3. 读取 40 位数据
  4. 校验数据
  5. 返回温度和湿度值

【调用关系】
  - 调用: DHT11_Start(), DHT11_ReadByte()
  - 被调用: App_Sensor_Task(), main()
```

### 7. 依赖分析

**问题类型**: "这个模块依赖哪些其他模块？"

**输出格式**:
```
=== 依赖分析 ===

【模块名】<模块名>

【直接依赖】
  - <模块1>: <说明1>
  - <模块2>: <说明2>

【间接依赖】
  - <模块3>: <说明3>
  - <模块4>: <说明4>

【头文件包含】
  - <头文件1>
  - <头文件2>
  - <头文件3>
```

**示例**:
```
=== 依赖分析 ===

【模块名】bsp_dht11

【直接依赖】
  - HAL 库: GPIO 初始化和操作
  - 延时函数: us 级延时

【间接依赖】
  - StdPeriphDriver: 底层驱动
  - CMSIS: ARM 内核支持

【头文件包含】
  - #include "stm32f10x.h"
  - #include "bsp_delay.h"
  - #include "bsp_dht11.h"
```

## 置信度说明

| 置信度 | 说明 | 示例 |
|--------|------|------|
| **高** | 源码和文档一致 | 引脚配置在代码和原理图中都确认 |
| **中** | 只有源码证据 | 代码中有配置，但没有文档说明 |
| **低** | 推测或不确定 | 根据代码推断，没有明确证据 |

## 输出格式选择规则

| 问题类型 | 输出格式 | 说明 |
|----------|----------|------|
| 简单问题 | 格式 1 | 快速回答 |
| 整体分析 | 格式 2 | 全面分析 |
| 功能列表 | 格式 3 | 列出所有功能 |
| 代码提取 | 格式 4 | 提供提取建议 |
| 代码搜索 | 格式 5 | 搜索结果列表 |
| 函数分析 | 格式 6 | 详细分析函数 |
| 依赖分析 | 格式 7 | 分析依赖关系 |
